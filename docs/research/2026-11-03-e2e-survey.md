# End-to-end (real-server) testing for Bukkit/Spigot/Paper/Folia plugins

Status: **historical research**, 2026-11-03. Written inside the Disenchantment repo and moved here as the
founding document of Proofstone.

> **Superseded in part.** This report recommended a Mineflayer sidecar as the bot. The long-term decision is an
> MCProtocolLib driver that speaks only the newest protocol, with ViaProxy translating for older servers, and
> Mineflayer kept as an independent *reference* driver for cross-checking. See
> [ADR-0004](../adr/0004-client-driver-latest-protocol-plus-viaproxy.md) and
> [ADR-0003](../adr/0003-dual-oracle.md). The survey, the prototype evidence and the lessons learned still apply.
Prototype: [`prototype-2026-11/`](prototype-2026-11/), a throwaway script that is not wired into Maven.

## TL;DR

- **It is feasible today, and it is proven.** The prototype boots Paper in Docker with the real
  `Disenchantment-6.5.12.jar`. A Mineflayer bot joins in offline mode, opens a real anvil, puts in a
  Sharpness V + Unbreaking III sword and a book, and takes the result. It asserts the outcome from both
  the client side and the server side. 8/8 checks pass on **Paper 1.18.2, 1.21.11, 26.1.2 and 26.3**
  (26.3 through ViaBackwards). Each cell boots in 20–30 s and the test itself runs in about 3 s.
- **Nothing reusable exists for a Maven/Java plugin with a version matrix and Folia.** The closest
  project is [Plugwright](https://github.com/Drownek/plugwright). It is Gradle-only, tests are written
  in JS/TS, it is Paper-only, and its GUI locators match items by name, not by slot.
- **Gaps that need building:**
  - a version-neutral **in-server agent** for setup and assertions. RCON truncates its output and breaks
    on Folia.
  - a **bot driver** that does not tie tests to one protocol version.
  - a **JUnit 5 matrix extension** that connects the pieces.
- **Recommendation:** use Testcontainers with the `itzg/minecraft-server` image, an agent plugin with an
  HTTP/JSON API, and a Mineflayer sidecar container exposed over JSON-RPC. Add ViaBackwards
  automatically when the server is newer than the bot. Publish it as Maven artifacts, a GHCR image and a
  GitHub Action.
- **Effort:** a Disenchantment-only MVP takes about 3–4 days. The reusable framework takes about
  4–6 developer-weeks.

## 2. Prototype evidence

Files are in [`prototype-2026-11/`](prototype-2026-11/) (`run.sh`, `e2e.js`). Runs used Docker Desktop on
Windows with the itzg image and `ONLINE_MODE=false`, a flat world and RCON.

| Server | Java image | Bot protocol | Boot (incl. Paper download) | Result |
|---|---|---|---|---|
| Paper 1.18.2 (NMS_v1_18_R1) | java17 | 1.18.2 | 19–20 s | 8/8 ✅ |
| Paper 1.21.11 (NMS_v1_21_R5) | java21 | 1.21.11 | 27–30 s | 8/8 ✅ |
| Paper 26.1.2 | java25 | 26.1 | 24–25 s | 8/8 ✅ |
| Paper 26.3 | java25 | 26.1 | 24 s | ❌ bot refused (`ECONNRESET`) |
| Paper 26.3 + ViaVersion/ViaBackwards (`MODRINTH_PROJECTS`) | java25 | 26.1 | 27 s | 8/8 ✅ |
| Folia 1.21.11 | java21 | 1.21.11 | 29 s | Client checks 6/6 ✅. Server checks ❌: Folia lacks `/data`, and `xp query` sends nothing back over RCON. |

The checks were: command round trip (`/version Disenchantment` returns a chat message), the sword starts
with its enchants, the result-slot preview is an `enchanted_book`, the book ends up with
`{sharpness:5, unbreaking:3}`, the sword is stripped, the client XP goes from 30 to 17 levels, the
server-side inventory has the book (`data get`), and the server-side XP dropped (`xp query`). The 13-level
cost comes from the default config.

Lessons that shape the design:

1. **RCON is too weak as an assertion channel.** Long SNBT gets truncated to `...` (on 26.1 even
   `data get … Inventory` was cut before the enchant list). Every version has its own command syntax:
   `give sword{Enchantments:[…]}` before 1.20.5, `sword[enchantments={…}]` after, `tag.StoredEnchantments`
   against `components."minecraft:stored_enchantments"`. On Folia some commands are missing and others
   reply asynchronously with nothing. This is why the design needs an agent plugin that uses the Bukkit
   API and returns JSON.
2. **Never assert after a fixed sleep.** On 1.18.2 the client inventory after `closeWindow` was
   intermittently stale for more than 500 ms, and one run timed out on `windowOpen`. Polling with
   `waitFor` fixed both. Every bot read needs an `await…(predicate, timeout)`.
3. **The client-side item model lags the protocol.** prismarine-item could not read stored enchants in
   the component era, and it reports enchantment IDs as numbers that have to be mapped through
   `bot.registry`. Server truth must come from the agent, and client reads are a secondary check.
4. **Older bots can reach newer servers through ViaBackwards** without trouble. The bridge is a
   translation layer, so mark such cells as "bridged" and keep at least one native cell per NMS module.
5. A small tooling note: in Git Bash, bind-mount paths must be Windows-style (`pwd -W`). Testcontainers'
   `copyFileToContainer` avoids that issue altogether.

## 3. Feasibility verdict and hard parts

**Possible today:** real Paper and Folia servers from 1.18 → 26.3 in CI, real protocol bots, scripted
anvil and grindstone interaction, and client plus server assertions. **Missing:** a reusable, typed,
version-neutral setup and assertion layer, a bot API usable from Java, and a JUnit matrix runner.

| Hard part | Assessment | Mitigation |
|---|---|---|
| **Offline-mode auth** | Easy. `ONLINE_MODE=false`, and bots use `auth:'offline'`, so UUIDs are derived from the name. 1.19+ chat signing did not get in the way (bot chat and commands worked). | Also set `enforce-secure-profile=false`. For Bedrock-prefix tests (`.Name`), Paper's username validation may need to be turned off (unverified). |
| **Version matrix 1.18 → 26.x** | Server side is solved: itzg plus the Paper fill API (`fill.papermc.io/v3`) cover every version. Java varies: **17** for ≤1.20.4, **21** for 1.20.5–1.21.x, **25** for 26.x. | The harness maps the MC version to an image tag. Pick one cell per NMS module (`v1_18_R1`, `v1_20_R4`, `v1_21_R1`, `v1_21_R4`, `v1_21_R5`) plus latest, about 6–7 cells. |
| **Protocol churn** | Main ongoing risk. Mineflayer trails the latest release (26.1 vs. 26.3 now). MCProtocolLib is current but supports one version per artifact. | Use ViaBackwards automatically when `server > bot.maxVersion`. Hide the bot behind an interface so it can be swapped (Mineflayer now, MCProtocolLib later). Keep item and enchant assertions on the agent side. |
| **Determinism and tick timing** | Moderate. Client/server sync is asynchronous, chunk sends race with `openBlock`, and the anvil result slot fills a tick after input. Disenchantment adds per-enchant `chance` rolls (`Math.random`) and cooldowns. | Use await-with-predicate everywhere, plus an agent `awaitTicks(n)` and `awaitState` on the server side. Use fixed spawn chunks (flat world, `VIEW_DISTANCE=4`, spawn protection 0, peaceful, `doDaylightCycle false`, `randomTickSpeed 0`) and reset the player before each test. The config fixture sets `chance=1.0`, or the agent seeds RNG if the plugin exposes it. Allow at most one retry, and record flaky cells. |
| **CI runtime and cost** | Fine. Per cell: image pull (~0.4–0.6 GB, cacheable), Paper download (~5 s, cacheable), boot 20–30 s, ~1 s join, about 3 s per test. 6–7 cells as parallel GitHub jobs take roughly **2–4 min wall clock** and about 20 runner-minutes per PR. | Public repo: free. Private: 2 000 free min/month covers about 100 PR runs. Cache `~/.m2`, Docker layers and the Paper jars (mount `/data/cache`, or pass `PAPER_DOWNLOAD_URL` to a cached jar). Run e2e only on PRs that touch `src/` (path filter), and nightly for the full matrix. |
| **EULA in CI** | The image refuses to start without `EULA=TRUE`. Setting it is standard practice and amounts to the repository owner accepting the [Minecraft EULA](https://www.minecraft.net/en-us/eula) for their own CI servers. | Make acceptance an explicit opt-in (`@McE2E(acceptEula = true)` or an env var `MC_EULA=true`) so the harness never accepts on a user's behalf by default. Don't redistribute server jars; download them at runtime from Paper's API. |
| **Folia** | The plugin loads and works under a real bot (prototype). Assertions must respect region ownership. | The agent runs player reads and writes on the player's `EntityScheduler`, block operations on the `RegionScheduler` and commands on the `GlobalRegionScheduler`, and completes a `CompletableFuture` for the HTTP reply. |
| **Bedrock** | Hardest piece and optional. Bedrock-only code paths can be reached cheaply via name-prefix detection (`BedrockDetectMethod`), so no Geyser is needed. | Tier 1: Java bot with the prefix name. Tier 2 (later): Geyser and Floodgate with `bedrock-protocol` once offline auth is proven. |

## 4. Architecture options

| | **A. All-Java bot** (MCProtocolLib) | **B. Java tests + Mineflayer sidecar** (recommended) | **C. Adopt Plugwright** | **D. In-server only** (agent and fake players, no network bot) |
|---|---|---|---|---|
| Test language | Java (JUnit) | Java (JUnit). The bot is a container speaking JSON-RPC. | TS/JS | Java (JUnit) |
| Host requirements | JDK + Docker | JDK + Docker (Node lives in the bot image) | Gradle + Node + JDK | JDK + Docker |
| Protocol realism | Full | Full | Full | **None**. Calls Bukkit/NMS directly and skips packets and client-visible results. |
| Version coverage | One per MCProtocolLib artifact. Needs N shaded copies or Via. | 1.8 → 26.1 natively, plus Via for newer | 1.8 → 26.1 | Every version (no protocol), but fake players need NMS per version |
| Inventory / window model | Build it yourself (slot sync, state IDs, hashed stacks on 1.21.5+) | Built in (`window.slots`, `clickWindow`) | Built in (name locators, no slot index) | Bukkit `InventoryView` |
| Server-side assertions | Agent | Agent | Console commands only | Native |
| Folia | Agent handles it | Agent handles it | Undocumented | Possible |
| Effort to build | High (2–3 wks for the bot model alone) | Medium | Low to adopt, high friction for Maven | Medium |
| Reusability for others | Good (pure Maven) | Good (Maven + image) | Already reusable (Gradle users) | Limited (not real e2e) |
| Main risk | Version churn × N | Two runtimes, plus Mineflayer lag | Lock-in to Gradle/JS, no Folia | False confidence |

**Why B wins:** Mineflayer already solves the hard client problems (window sync, item parsing,
1.8 → 26.1). Packaging it as a Docker image keeps Node off the developer's machine. Tests stay in Java
and the agent is shared, so the bot backend can later be swapped for MCProtocolLib (option A) behind
the same `Bot` interface without rewriting tests. Option D works as a cheap add-on tier: "agent-only"
tests with no bot, for things like server-side config validation and commands.

## 5. Recommended design (working name `mc-e2e`)

```
JUnit 5 test (Java)
  │  @McE2E / @McTest(matrix)            ┌─────────────── Docker network ───────────────┐
  ├── McServer ── Testcontainers ──────► │ itzg/minecraft-server:<javaTag>               │
  │      └── Agent client (HTTP/JSON) ──►│   plugins/: <plugin under test>, mc-e2e-agent  │
  │                                      │   (+ ViaVersion/ViaBackwards if bridged)       │
  └── Bot client (JSON-RPC/WebSocket) ──►│ ghcr.io/…/mc-e2e-bot:<ver> (Node + Mineflayer) │
                                         └───────────────────────────────────────────────┘
```

### 5.1 Components

1. **`mc-e2e-agent` (server plugin, a single jar for every version).** It is built against Spigot API 1.18
   with Java 17 bytecode, and uses reflection for Paper and Folia schedulers. It has no NMS and relies on
   JDK `com.sun.net.httpserver` for the HTTP API, with a token from an env var.
   - `POST /command` runs a console command and returns its captured output, scheduled on the main or
     global thread.
   - `POST /players/{name}/reset` resets the player: clears inventory, sets XP to 0, sets survival mode,
     heals, teleports to the fixture spot and clears the cursor.
   - `POST /players/{name}/give` with a version-neutral item spec, for example
     `{type, amount, enchants, storedEnchants, name, lore, pdc}`. The agent builds it with the Bukkit API,
     so tests never deal with SNBT or component syntax.
   - `GET /players/{name}` returns `{level, exp, gamemode, location, cursor, openInventory{type, slots[]},
     inventory[]}`. Items are serialized to the same JSON spec.
   - `POST /world/block` (`setblock`) and `GET /world/block`.
   - `PUT /plugins/{plugin}/config` patches YAML and reloads, through `onDisable`/`onEnable` or a plugin
     hook, and can snapshot and restore between tests.
   - `POST /events/subscribe {class}` and `GET /events/{id}` register a listener reflectively for any
     `Event` class name and serialize its getters to JSON. This lets tests assert on `PostDisenchantEvent`
     `xpCost` and `economyCost`.
   - `GET /ticks` and `POST /ticks/await {n}` read and wait on the tick counter.
   - `GET /log?level=WARN&since=` captures SEVERE/WARN lines and stack traces through a root
     `java.util.logging` Handler, for `assertNoErrorsLogged`.
   - Folia: per-entity, region and global schedulers. Every handler returns a `CompletableFuture`.
2. **`mc-e2e-bot` image (Node 24 + Mineflayer, pinned).** Serves JSON-RPC over WebSocket:
   - Connection: `connect{name, host, version}`, `quit`.
   - Chat: `chat`, `awaitMessage{regex, timeout}`.
   - Movement: `lookAt`, `goto` (optional pathfinder).
   - Windows: `openBlock{x,y,z} → windowId`, `window() → slots[]`, `click{slot, button, mode}`,
     `closeWindow`.
   - State: `inventory()`, `experience()`.
   - Item JSON matches the agent's schema, including the `stored_enchantments` component fix. The image
     advertises `maxProtocolVersion`.
3. **`mc-e2e-junit` (Maven artifact).**
   - `@McE2E(plugins=…, acceptEula=…)` boots the server once per class per matrix cell. It copies jars in
     with `copyFileToContainer`, waits for `Done (` and the agent's `/health`, and adds Via plugins when
     the server is newer than the bot.
   - `@McTest` is a `@TestTemplate` that produces one invocation per `@Server` cell. Cells can be
     filtered with `-Dmc.e2e.cells=1.21.11,26.3`.
   - Parameter resolvers inject `McServer`, `Agent` and `Bot`. Bots are fresh per test with unique names.
     The player is reset before each test, and config is restored after each test.
   - Await helpers (`awaitState`, `awaitSlot`) use Awaitility-style polling with timeouts printed in
     failures.
   - On failure, the extension attaches the server log tail, the agent's last state dump and the bot
     transcript to the JUnit report.
4. **Build integration.** Tests are named `*E2E.java` and run by `maven-failsafe-plugin` under
   `-Pe2e`, so `mvn test -pl core --offline` stays as it is. Testcontainers skips cleanly when Docker
   is missing, using `@Testcontainers(disabledWithoutDocker = true)`.

### 5.2 Packaging and publishing (for other plugin authors)

- Maven Central: `io.github.<org>:mc-e2e-junit`, plus `mc-e2e-agent` as a classified jar. The extension
  resolves the agent from the classpath, so users add just one dependency.
- GHCR: `ghcr.io/<org>/mc-e2e-bot:<mineflayer-version>`, rebuilt by Renovate when Mineflayer or
  minecraft-data release.
- GitHub Action `<org>/mc-e2e-action@v1`, a composite action that:
  - sets up the JDK,
  - restores the Docker, Paper-jar and `~/.m2` caches,
  - runs `mvn -Pe2e verify` (or `./gradlew e2eTest`),
  - uploads JUnit XML and server logs.

  It accepts a `cells` input so one matrix job can run per cell.
- Gradle users get the same JUnit artifact, and an optional small Gradle plugin can configure the
  source set.
- A version map (`mc → java image tag, max bot protocol, needs Via`) ships as data in the artifact and
  is updated by a scheduled workflow from the Paper fill API.

## 6. Example: Disenchantment anvil test in the harness

```java
@McE2E(plugins = "target/Disenchantment-*.jar", acceptEula = true)
@Server(platform = PAPER, version = "1.18.2")   // NMS_v1_18_R1
@Server(platform = PAPER, version = "1.20.6")   // NMS_v1_20_R4
@Server(platform = PAPER, version = "1.21.4")   // NMS_v1_21_R1
@Server(platform = PAPER, version = "1.21.7")   // NMS_v1_21_R4
@Server(platform = PAPER, version = "1.21.11")  // NMS_v1_21_R5
@Server(platform = PAPER, version = "26.3")     // LATEST fallback; bot bridged via ViaBackwards
@Server(platform = FOLIA, version = "1.21.11")
class AnvilDisenchantE2E {

    @BeforeEach
    void config(Agent agent) {
        // remove randomness: every enchant transfers
        agent.plugin("Disenchantment").patchConfig("disenchantment.enchantment-chances", Map.of());
    }

    @McTest
    void disenchantMovesEnchantsToBookAndChargesXp(Agent agent, Bot bot) {
        var player = agent.player(bot.name())
                .reset()
                .level(30)
                .give(Item.of("diamond_sword").enchant("sharpness", 5).enchant("unbreaking", 3))
                .give(Item.of("book"));
        BlockPos anvil = player.location().offset(2, 0, 0);
        agent.world().setBlock(anvil, "anvil");
        var post = agent.events().subscribe("com.jankominek.disenchantment.events.api.PostDisenchantEvent");

        try (Window w = bot.openBlock(anvil)) {
            assertThat(w.type()).isEqualTo("minecraft:anvil");
            w.moveFromInventory(i -> i.is("diamond_sword"), 0);
            w.moveFromInventory(i -> i.is("book"), 1);

            ItemView preview = w.awaitSlot(2, i -> i.is("enchanted_book"));    // client sees plugin result
            assertThat(preview.storedEnchants()).containsOnly(entry("sharpness", 5), entry("unbreaking", 3));

            w.click(2, LEFT_CLICK);              // plugin moves the book onto the cursor
            w.dropCursorIntoFirstEmptySlot();
        }

        // server truth via agent (Bukkit API, version-neutral JSON)
        PlayerState s = player.awaitState(p -> p.inventory().contains("enchanted_book"));
        assertThat(s.inventory().first("enchanted_book").storedEnchants())
                .isEqualTo(Map.of("sharpness", 5, "unbreaking", 3));
        assertThat(s.inventory().first("diamond_sword").enchants()).isEmpty();

        int xpCost = post.awaitOne().getInt("xpCost");
        assertThat(xpCost).isPositive();                  // 13 with default config (observed)
        assertThat(s.level()).isEqualTo(30 - xpCost);     // XP drop matches the API event
        assertThat(bot.experience().level()).isEqualTo(30 - xpCost);   // and the client agrees

        agent.assertNoErrorsLogged();
    }
}
```

Using the same building blocks, the follow-ups are:

- `shatterSplitsOneEnchant`
- `grindstoneExtract` (`openBlock` on a grindstone, slots 0/1 → 2)
- `unsafeShiftClickOnResultIsCancelled` (`click(2, SHIFT)`, assert no duplicate)
- `insufficientXpBlocksResult`
- `disabledWorldShowsVanillaResult`
- `bedrockPrefixPlayerGetsChestMenu` (bot named `.E2EBot`, prefix detection)

## 7. Effort estimate

| Item | Estimate |
|---|---|
| **MVP for Disenchantment only.** Harden the prototype into `e2e/` with Node and RCON, add 5–6 scenarios, a GitHub Actions matrix (one job per NMS module plus latest), caching, and a path filter. | 3–4 days |
| Agent plugin (HTTP API, item JSON, event probe, log capture, Folia schedulers) | 4–6 days |

| JUnit extension (Testcontainers wiring, matrix template, resolvers, reset/restore, failure artifacts, Via auto-bridge) | 4–6 days |
| Disenchantment suite on the harness (anvil, shatter, erase, grindstone, special anvils, Bedrock prefix) | 3–5 days |

| Publishing (Central, GHCR, docs site, sample project) | 2–3 days |
| **Reusable framework total** | **≈ 4–6 developer-weeks** |

Suggested order: MVP first, since it delivers value now and finds real bugs. Then extract the agent,
because it is the most reusable part and replaces RCON. After that build the JUnit extension, and the
bot image last.

## 8. Open questions

1. Should the reusable framework be **built from scratch or contributed to Plugwright**? Plugwright
   could gain a Maven/Java front end, Folia support and agent-based assertions. Owner preference and
   upstream appetite are both unknown.
2. **Repo home:** a separate `mc-e2e` repo and organisation, or incubate under `Disenchantment/e2e/`
   first?
3. **Bedrock tier 2:** can `bedrock-protocol` with `offline: true` join Geyser using
   `auth-type: offline` or Floodgate without Xbox auth? This needs a spike. Does Paper's username
   validation reject `.`-prefixed offline names?
4. **Randomness:** should Disenchantment expose a test seam (seeded RNG or "chance = 1.0" via config)
   for deterministic chance tests? Config probably covers it.
5. **Matrix size:** run all 7 cells on every PR, or only 1.21.11 + latest on PRs and the full matrix
   nightly?
6. **Via-bridged cells:** accept them as proof for "latest", or wait for Mineflayer and allow the
   latest cell to fail?
7. **Spigot (non-Paper) servers:** itzg can build Spigot with BuildTools, but it is slow (minutes). Is
   coverage on Paper only acceptable, given the plugin targets Spigot too?
8. **CI host:** GitHub-hosted Ubuntu runners have Docker, and Windows/macOS runners don't support Linux
   containers. Is Linux-only e2e acceptable?
